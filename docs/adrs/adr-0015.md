# ADR-0015: Per-Clip Audio Licensing, with Speaker Consent Tracked Outside the Repository

## Status

✅ Accepted

## Context

A recording is not the same kind of thing as a dictionary fact. **A recorded performance is
copyrightable separately from the phonological fact it captures**, so a clip cannot ride on the
licence of the entry it is attached to. Clips also come from more than one place: original
recordings by project contributors, and imports from Lingua Libre via Wikimedia Commons, where the
category default is CC-BY-SA-4.0 but a meaningful share of files report CC-BY-4.0 or CC0 instead.

And there is a concern copyright licensing does not cover at all: a person's **consent to have
their voice released**. A licence answers "may this be redistributed"; it does not answer "did the
speaker agree to be recorded and published".

## Decision

**A clip's licence derives from its own `sources`, exactly as an entry's does** (ADR-0008) —
independently of the entry it is attached to.

- Original recordings cite `teochew-dictionary-audio`, a `kind: import` source licensed CC-BY-4.0
  (issue #33). Because CC-BY-4.0 is already `BASE_LICENCE`, this needed no new `LICENCE_CLASS`
  entry and no new `LICENSE-DATA-AUDIO-*` file — `LICENSE-DATA-CC-BY-4.0` gained a header paragraph
  saying it also covers audio, rather than a parallel file with identical legal text.
- **CC0 was rejected** for original recordings: every other data category here requires attribution
  even when permissive, and CC0 would make audio the one category owing nothing, for no offsetting
  benefit. CC-BY-4.0 also gives a volunteer speaker formal credit, which matters more for a
  recorded voice than for an imported dictionary fact.
- Lingua Libre imports cite whichever of `lingualibre` / `lingualibre-ccby4` / `lingualibre-cc0`
  matches the **file's own Commons-reported licence** — never the category default (issue #106).

So a clip's licence can differ from its entry's, and from another clip on the same entry. The web
UI dedupes and credits distinct clip licences separately rather than assuming the entry's covers
them.

**Speaker credit is not attribution.** Per-clip credit lives in the clip's own `speaker` field
(a pseudonymous identifier for original recordings; the Commons uploader's real username for
imports), not in `attributions` — every original clip cites the one CC-BY-4.0 source, so the
attribution machinery has nothing to say. `speaker` is deliberately **not** part of
`AudioReference`, so it never reaches `dist/dict.json`: it is source-data-only.

**Consent is a separate, manual process, tracked outside the repository** —
[AUDIO-CONSENT.md](../../AUDIO-CONSENT.md) describes it, and no tooling automates or verifies it.
Tools carry guardrails, not proof: the browser record flow requires a speaker pseudonym and an
explicit "I have obtained consent" acknowledgement before saving, the same way
`merge:lingualibre` requires `--variety` with no default.

## Consequences

- Mixed-licence audio is representable and correctly reported, so a consumer filtering to
  permissive material gets a truthful answer at clip granularity.
- Recording a real person is treated as its own concern rather than a copyright footnote, and the
  distinction between "licensed" and "consented" stays visible in the design.
- Reusing the existing licence-resolution machinery meant audio needed no parallel implementation —
  ADR-0008's rule applied to a new `sources`-carrying object.
- Negative: **consent is unverifiable from the repository.** The acknowledgement checkbox is a
  guardrail against clicking past the requirement unnoticed, not evidence the conversation happened.
  This is stated plainly rather than papered over.
- Negative: keeping `speaker` out of `dist/dict.json` means a consumer cannot credit an individual
  speaker from the published artifact, only the project. Deliberate — publishing pseudonyms into a
  redistributable dataset is a larger decision than crediting them in source data.
