# ADR-0006: Importers Write Only to `data/staging/`

## Status

✅ Accepted

## Context

The lexicon grows by importing: CC-CEDICT for Mandarin glosses, Wiktionary for Teochew readings,
Lingua Libre/Commons for audio. The efficient thing for an importer to do is write straight into
`data/entries/`.

Two forces make that the wrong efficiency:

- **Licence contamination.** Wiktionary and CC-CEDICT are CC-BY-SA-4.0. Merging their glosses
  relicenses the receiving entry as share-alike (ADR-0008). An importer that writes to
  `data/entries/` silently relicenses the dataset one entry at a time, with nobody deciding.
- **CC-CEDICT is a Mandarin dictionary.** It carries no Teochew pronunciation whatsoever. Letting a
  Mandarin source populate a Teochew reading would be the single most damaging error available in
  this project — a dictionary that is confidently wrong about the language it documents.

## Decision

Importers write **proposals** to `data/staging/`, never to `data/entries/`. Merging is a human act.

- Staged files are deliberately **not in entry-file format**, so they cannot be dropped in
  unedited. One file per source: `wiktionary.yaml`, `lingualibre.yaml`,
  `teochew-dictionary-audio.yaml`.
- The CC-CEDICT importer *cannot* propose a reading by construction — only glosses for headwords
  that already exist.
- Wiktionary readings are validated as Peng'im before being proposed; malformed candidates are
  reported rather than imported. The Wiktionary importer never fetches a gloss at all: readings and
  glosses are separate licence decisions, so writing a gloss requires a human reading the page.
- The rule is a property of importers as a category, stated in
  [src/importers/types.ts](../../src/importers/types.ts), not of any one importer. The two
  maintenance backfills that *do* write to `data/entries/`
  (`backfill:wiktionary-tags`, `backfill:mandarin-level`) are deliberately **not** importers — they
  are one-off scripts editing already-approved data, and they are structured accordingly (dry-run
  by default, `--write` to commit; see ADR-0018).

## Consequences

- Relicensing an entry is always a deliberate act with a name attached to it. As of the Swadesh-207
  merge (issue #5, 2026-07-31), the dataset is a genuine mix: 103 entries cite only `seed` and stay
  CC-BY-4.0, 141 cite `wiktionary` and are CC-BY-SA-4.0 — a split that only stays meaningful
  because no script created it.
- A wrong import is contained. A bad proposal sits in `data/staging/` where it can be deleted; it
  never reaches a consumer.
- Negative: this is the project's dominant cost. The 15,845 `staged` Wiktionary candidates each
  needed a human to read a page and write a gloss, which is why issue #68 was worked in many small
  batches (`npm run batch:wiktionary`) rather than one merge. The friction is the point, but it is
  real friction — it is what the whole of issue #68 consisted of.
- The staging boundary is what the resumable-import design (ADR-0010) and the page cache
  (ADR-0013) exist to make survivable at that scale.
- Extended to the browser in ADR-0017: a UI that records audio also stages, rather than publishing.
