# ADR-0010: Grow the Lexicon Against Checklists with a Defined Denominator

## Status

✅ Accepted

## Context

A dictionary built by adding whatever entry occurs to someone next has no answer to "how complete
is this?". Coverage is unmeasurable, gaps are invisible, and there is no way to tell a contributor
what would help most. Ad-hoc growth also produces a lexicon shaped by whoever contributed rather
than by what a learner needs.

The project needs a *denominator*: a defined set to be complete against.

## Decision

Growth is tracked against checklists in [data/wordlists/](../../data/wordlists/), each with an
explicit `status` lifecycle per item. Three kinds, deliberately different:

- **[swadesh-207.yaml](../../data/wordlists/swadesh-207.yaml)** — the Swadesh 1971 basic-vocabulary
  list. **Hand-maintained**, not script-regenerated: each item's Teochew headword is a curation
  decision, and a script cannot make it. Statuses: `existing`, `to_fetch`, `staged`, `no_reading`.
- **[wiktionary-teochew-index.yaml](../../data/wordlists/wiktionary-teochew-index.yaml)** (issue
  #54) — the same lifecycle at a different scale and origin, script-enumerated (ADR-0011). No
  headword curation is needed because the Wiktionary page title already *is* the headword. It adds
  one status the Swadesh list lacks: **`no_gloss`**, a terminal state a human sets by hand — never
  an importer — after confirming a `staged` headword's page gives no independently definable
  content (bound character, compound-only note, unfilled stub) despite carrying a valid reading.
- **[syllable-inventory.yaml](../../data/wordlists/syllable-inventory.yaml)** (issue #30) — every
  legal Peng'im syllable the orthography allows, one row per variety-tagged attestation. Fully
  **script-regenerated** by `npm run inventory`, because it is 100% derivable from `pengim.yaml`
  and `data/entries/`. It is committed anyway, and `npm run check` rebuilds it in memory and
  asserts it equals the committed copy ([tests/inventory.test.ts](../../tests/inventory.test.ts)),
  so a stale file fails the build.

At the scale the Wiktionary index reaches, fetching has to be **resumable**:
`npm run import -- wiktionary --from-wordlist --limit=500` sources `to_fetch` items from the
checklist instead of argv, **merges** its results into `data/staging/wiktionary.yaml` instead of
overwriting it, and flips each processed headword to `staged`/`no_reading` — so rerunning the same
command picks up only what remains.

## Consequences

- **Coverage is a number.** As of writing: 191 of the Swadesh-207 items are `existing` and 16
  remain `no_reading`; the Wiktionary index has been worked to completion — 16,031 `existing`, 53
  `no_gloss`, 1,091 `no_reading`, none still `staged`. The "most valuable next contributions" list
  is derivable rather than asserted.
- Work is parallelisable and interruptible. A contributor can take a batch without coordinating,
  and a batch that dies halfway loses only its own progress.
- The syllable inventory's regenerate-and-diff pattern gives a derived artifact that is both
  reviewable in a PR (you can see which syllables a change attests) and guaranteed fresh.
- Negative: three checklist kinds with overlapping-but-unequal `status` vocabularies is a real
  concept count. The `no_gloss` state in particular exists only in one of them.
- Negative: a denominator is also a bias. Swadesh-207 defines "basic vocabulary" for comparative
  linguistics, not for a learner of Teochew specifically; the Wiktionary index defines coverage as
  "what Wiktionary happens to document". Both are stated denominators rather than claims of
  completeness.
- Negative: `syllable-inventory.yaml` is large and regenerating it is slow enough that its test
  needed a 30s timeout.
