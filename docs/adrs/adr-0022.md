# ADR-0022: Derive CEFR `level` from HSK Cognates; Reject an HSK 3.0 Crosswalk

## Status

✅ Accepted

## Context

`frequency` (1 rare … 5 core everyday) answers *how common is this word*. It does not answer *when
should a learner meet it* — a common word can be late-taught, and a rare one early-taught. A
flashcard trainer that can only order by corpus commonness cannot build a beginner's deck.

The normal solution is to import a graded curriculum. **No ready-made leveled system exists for
Teochew.** The nearest analogues are Taiwan's GTPT for Hokkien and raw corpora; nothing HSK-shaped
covers this language. So a level has to be derived rather than imported, from whatever signal has
usable open material today.

The one such signal is **shared-hanzi cognacy with Mandarin HSK vocabulary**: a Teochew headword
written with the same characters as an HSK word is, roughly, taught at a comparable stage.

## Decision

`entrySchema.level` is a **CEFR A1–C2 tier**, distinct from `frequency`.
`npm run backfill:mandarin-level -- <path/to/complete.json> [-- --write]` (issue #110) matches each
entry's headword and variants against a local copy of
[`drkameleon/complete-hsk-vocabulary`](https://github.com/drkameleon/complete-hsk-vocabulary) and
writes `level:` onto already-merged entries, using the same dry-run-by-default, byte-offset-splice,
only-fill-if-absent script shape as the tag backfill (ADR-0018). Matching logic lives separately in
[src/importers/mandarin-cognate-level.ts](../../src/importers/mandarin-cognate-level.ts) so it is
unit-testable. `hsk-vocabulary` is registered `kind: reference` (ADR-0009) — the band is consulted
to derive a level, never reproduced — so no entry cites it in `sources:`.

Two deliberate limitations, both because **guessing is worse than an entry staying untiered**:

- **Exact whole-headword hanzi match only**, no character-level decomposition. A Teochew
  multi-character headword that does not line up with HSK's own word boundaries is left unmatched.
- **HSK 2.0's `old-1`–`old-6` bands only**, mapped `old-1`/`old-2`→A1, `old-3`→A2, `old-4`→B1,
  `old-5`→B2, `old-6`→C1 — the correspondence most commonly cited for HSK 2.0. **HSK 3.0's `new-N`
  bands (1–9) are deliberately not crosswalked.** China's Center for Language Education and
  Cooperation describes only its three coarse stages (elementary/intermediate/advanced) as
  corresponding to CEFR's A/B/C and has published no official level-by-level table, so a word with
  only a `new-N` band is left unmatched rather than mapped off an invented table.

No `old-N` band reaches C2, so a C2 `level` can only come from a future signal or a human's hand
edit.

## Consequences

- The web UI can filter and group by level
  ([levelFilter.ts](../../packages/core/src/flashcards/levelFilter.ts) in `@teochew/core`, issues
  #113/#163), which is what makes a beginner-appropriate flashcard deck constructible.
- The derivation is cheap, reproducible and reviewable: one reference dataset, one matching rule, a
  dry run before any write.
- **Refusing the HSK 3.0 crosswalk keeps `level` honest.** An invented `new-N`→CEFR table would have
  produced more coverage and less truth, and the absent field is a legible gap where a wrong tier
  would not be.
- Negative: **coverage is limited and biased toward Sinitic-cognate vocabulary.** Words with no
  Mandarin cognate — a large and important part of Teochew — get no level from this signal at all,
  so `level` is systematically sparser exactly where the language is most itself.
- Negative: the level is Mandarin's curriculum difficulty standing in for Teochew's. Stated as an
  approximation, not a measurement.
- Neutral: the other two signals from issue #110 — Hokkien cognacy via Taiwan's GTPT/MOE material,
  and Teochew-internal corpus frequency — plus phrase and idiom tiering, are follow-up work.
