# ADR-0025: Anonymous Visit Counts via GoatCounter

## Status

✅ Accepted

## Context

There is no way today to tell how many people use the dictionary, or whether a given change to
the web UI moves usage at all. Builds on [ADR-0019](adr-0019.md): `web/` is a static,
backend-free app deployed to GitHub Pages, so there are no server access logs to mine. GitHub's
own repository Traffic tab exists, but it is a 14-day rolling window visible only to repo admins
— too coarse and too narrow to answer "is anyone using this" over time.

Any real count has to come from a script the browser runs on each visit, reporting to a service
this project does not operate — running one itself would reintroduce the server ADR-0019
deliberately avoided. This is also the project's *first* analytics or tracking capability of any
kind, so there is no existing privacy precedent in the repo to extend, and none of the existing
documentation (root `README.md`, `web/README.md`) says anything about what the app does or does
not collect.

## Decision

Count visits with **[GoatCounter](https://www.goatcounter.com/)**: free for non-commercial and
open-source use, cookieless, and does not collect or store anything that identifies an individual
visitor (no fingerprinting, no cross-site tracking, IP address discarded after deriving a
country/region). It is cloud-hosted, so nothing new needs to be run or maintained, keeping
ADR-0019's "zero hosting cost and zero operational burden" intact.

Concretely:

- A single, static, unconditional `<script>` tag in `web/index.html`'s `<head>`:
  ```html
  <script data-goatcounter="https://teochew-dictionary.goatcounter.com/count" async src="//gc.zgo.at/count.js"></script>
  ```
  No new npm dependency — this is a plain script tag, not an SDK, matching the project's
  preference for small, legible implementations over adding a library
  ([ADR-0023](adr-0023.md)'s Workbox exception aside).
- **Always on, not gated behind a Settings toggle.** Because GoatCounter is cookieless and
  collects no PII, it needs no cookie-consent banner, and there is no per-visitor state to let a
  toggle turn off — unlike `showLicence` or `mogherLinks` in Settings, there is nothing here for
  an individual visitor's choice to act on beyond disclosure.
- **Disclosed on the About page** (`web/src/views/AboutView.tsx`), naming GoatCounter, stating
  what is and is not collected, and linking to GoatCounter's own privacy policy — in the same
  spirit as issue #66's "show disclosure by default, not behind an opt-in toggle."

## Consequences

- The app makes one new third-party network request on every page load (to `gc.zgo.at` and the
  project's `*.goatcounter.com` subdomain). The script is `async` and non-blocking, and the
  Cache Storage precache list in `vite.config.ts` only ever covers the app shell
  (`js/css/html/png/svg/ico`, per ADR-0023) — the analytics request is never precached, and
  simply fails silently offline or if a visitor's browser blocks it, like any other blocked
  third-party script.
- No PII or cookies collected; no cookie-consent banner needed. First privacy-relevant disclosure
  the project has ever needed to write.
- New dependency on GoatCounter's uptime and continued free tier for open-source projects — if
  either changes, the ADR would need revisiting, but the app's core functionality never depends
  on it.
- Visit counts are visible only on the GoatCounter dashboard for whoever holds the account; there
  is no public stats page unless a maintainer chooses to make one public later.

## Alternatives considered

- **Cloudflare Web Analytics.** Also free and cookieless, but ties the project to a Cloudflare
  account for no advantage over GoatCounter, which is itself open source.
- **Plausible.** Clean dashboard and a similar privacy stance, but the cloud-hosted version has
  no free tier, and self-hosting it would mean running a server — the exact thing ADR-0019
  rejected.
- **GitHub repository Traffic insights alone.** No code to write, but a 14-day window visible
  only to admins is too coarse to track usage over time or share externally.
- **A self-hosted counting endpoint** (e.g. a small serverless function incrementing a counter).
  Rejected for the same reason as self-hosting Plausible: it reintroduces a backend this project
  has deliberately stayed without.
