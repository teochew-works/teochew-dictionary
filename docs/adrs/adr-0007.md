# ADR-0007: License Code and Data Separately

## Status

✅ Accepted

## Context

The project started under a single licence, BSD-3-Clause, covering everything (2026-07-25). That is
the path of least resistance and it is what most repositories do.

It does not fit. A lexicon is not software:

- A software licence's operative language — "redistributions of source code", "in binary form" —
  has no referent in a dataset. What is the binary form of a dictionary entry?
- Only the Creative Commons family addresses ***sui generis* database rights**: the EU-style right
  over a *compilation*, separate from any copyright in the individual facts it contains. A plain
  software licence is silent on it, which means a downstream reuser in a jurisdiction that
  recognises the right has no grant covering it.
- It is not the idiom of the field. Wiktionary, iTaigi and Tatoeba all license lexical data under
  CC. Using BSD would make this dataset harder to combine with the projects it most wants to be
  combinable with.

## Decision

We will license **code and data separately**, deliberately.

|                                               | Licence                                    | File                                                                 |
|-----------------------------------------------|--------------------------------------------|----------------------------------------------------------------------|
| `src/` — the tooling                          | BSD-3-Clause                               | [LICENSE](../../LICENSE)                                             |
| `web/` — the frontend app                     | BSD-3-Clause                               | [LICENSE](../../LICENSE)                                             |
| `data/` — default                             | CC-BY-4.0                                  | [LICENSE-DATA-CC-BY-4.0](../../LICENSE-DATA-CC-BY-4.0)               |
| `data/` — entries citing a share-alike source | CC-BY-SA-4.0                               | [LICENSE-DATA-CC-BY-SA-4.0](../../LICENSE-DATA-CC-BY-SA-4.0)         |
| `data/` — attribution owed to `unihan`        | Unicode-DFS-2016                           | [LICENSE-DATA-UNICODE-DFS-2016](../../LICENSE-DATA-UNICODE-DFS-2016) |
| `data/phonology/audio/` — imported clips      | CC-BY-SA-4.0 / CC-BY-4.0 / CC0, per source | per-licence file                                                     |

CC-BY-4.0 is the data default (`BASE_LICENCE` in
[src/data/licence.ts](../../src/data/licence.ts)) — permissive, attribution-only, and the common
denominator of the ecosystem. Every distinct licence text a source can carry gets its own
`LICENSE-DATA-*` file at the repo root rather than being paraphrased in the README.

Split from the single code licence in issue #6 (2026-07-29).

## Consequences

- The tooling stays maximally reusable under BSD-3-Clause while the dataset carries obligations
  appropriate to a compilation of facts, including database rights.
- The dataset can be combined with Wiktionary-derived and other CC-licensed lexical material
  without a licence-compatibility argument.
- Because the data licence is *not* uniform, it has to be computed per entry rather than declared
  once — which is ADR-0008.
- Negative: contributors must understand that a PR touching `src/` and `data/` touches two licence
  regimes. Mitigated by the boundary being the directory structure, which is already the project's
  main organising principle (ADR-0005).
- Negative: more `LICENSE-DATA-*` files at the repo root than a single-licence project has. That is
  the cost of not paraphrasing legal text.
