# ADR-0013: A Shared, Symlinked `.cache` Outside Any Checkout

## Status

✅ Accepted

## Context

Once headword enumeration reached five figures (ADR-0011), the per-headword network fetch became
the dominant cost of merging. The merge pass reads each candidate's Wiktionary page to write a
gloss, and the audit pass reads the same page again to check the result — and none of those fetches
survive an interruption. A subagent that dies halfway through a batch re-downloads everything.

The cached material is also large and, in one case, enormous. kaikki.org publishes a combined
wiktextract dump of all Wiktionary content: `raw-wiktextract-data.jsonl` is ~24.5 GB decompressed
(10.8M lines), grepped down to a 526 MB `teochew-relevant.jsonl` (32,167 lines) and trimmed to a
~13.8 MB `teochew-relevant.min.jsonl` — a 97.4% byte reduction that is what makes the file small
enough to load whole rather than index.

This project is worked in multiple git worktrees. A cache directory inside a checkout would be
re-downloaded per worktree — 24.5 GB at a time — and would show up as an untracked path.

## Decision

**`.cache` must be a symlink to a directory outside any checkout**, shared by every worktree of the
repo.

`npm run cache:wiktionary` (issue #79) **refuses to run** — rather than silently creating a plain
directory — if `.cache` is missing, is not a symlink, or points at something that isn't an existing
directory. The one exception: a fresh `git worktree` starts with no `.cache`, so if the main
checkout already has a working symlink, the command **mirrors it** into the new worktree
automatically instead of making that a manual step every time.

It caches **every** headword in the Wiktionary index whatever its `status`, not just the `staged`
ones — an already-merged `existing` entry is exactly what a later re-verification pass needs its
source page for.

The layout the symlink points at (issue #84, documented in the README):

```
wiktionary-pages/                one file per headword, raw wikitext        (#79)
raw-wiktextract-data.jsonl       full kaikki.org dump, ~24.5 GB, disposable (#84)
teochew-relevant.jsonl           grepped to Teochew-relevant lines, 526 MB  (#84)
teochew-relevant.min.jsonl       trimmed to the fields used, ~13.8 MB       (#84)
```

Each is derived from the one above it, so only the last one actually read has to survive. Path
constants live in [src/paths.ts](../../src/paths.ts) (`CACHE_DIR`,
`WIKTIONARY_PAGE_CACHE_DIR`, `WIKTEXTRACT_MIN_FILE`).

## Consequences

- **The expensive reasoning step is decoupled from the flaky network one.** `cache:wiktionary`
  downloads over plain HTTP with no model involved; the merge pass then reads local files, and an
  interrupted batch resumes for free.
- Tens of gigabytes are fetched once per machine, not once per worktree.
- The refuse-to-run check turns a silent misconfiguration — a plain `.cache/` directory quietly
  accumulating inside a checkout — into an immediate error, and the auto-mirror keeps the strictness
  from taxing the normal worktree workflow.
- Negative: **one-time manual setup.** A new clone does not work until someone creates the symlink.
  This is stated in the README and enforced by the error message, not automated.
- Negative: the *layout* inside the shared directory is convention, not enforcement. Only the
  symlink itself is checked; nothing stops the kaikki files being put elsewhere.
- Negative: a shared cache is shared staleness. A page cached once is not refetched.
- Nothing in the repo reads `teochew-relevant.jsonl` in its untrimmed form; producing the trimmed
  file and teaching passes to prefer it over a live fetch were kept as separate steps.
